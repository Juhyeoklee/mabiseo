# 코딩 컨벤션

코드 리뷰어(`.claude/agents/mabiseo-reviewer.md`)의 유일한 기준이다. 주석 규칙은 `.claude/rules/comments.md`가 따로 진다.

## 1. 계약 — 기계가 못 막는 것

- 날개를 쓰는 호출(채집 · 가공 등록 · 제작 · 그 밖의 맡기기)은 반드시 `tools/`의 보호 장치를 거친다
- 활동은 한 번에 하나다. 새 활동은 앞 활동을 조용히 취소하므로, 겹쳐 부르는 경로가 코드에 있으면 안 된다
- 1시간 확인 팝업과 채팅 승인을 자동화하지 않는다. 감지와 알림까지만 한다
- 공지가 「불가」로 둔 영역(거래소 · 성장 자동 플레이 · 결제 · 길드 운영 · 1:1 대화 · 버리기 · 분해 · 외부 메신저 연동)을 도구로 내놓지 않는다

## 2. 의존 방향

- `agent/ → tools/ → connector/` 한 방향이다. `agent/`가 `connector/`를 import하면 보호 장치가 우회된다
- CLI 실행(`child_process`)은 `connector/` 한 곳에만 있다. `scripts/`의 녹화 도구는 이 규칙 밖이다. 날개를 쓰지 않는 호출만 부르고, 실행 명령은 거부가 확실한 상태(없는 이름 · 게임 밖)에서만 부른다. 채팅은 보내지 않는다. 그 산출물이 `connector/`의 재료다
- 두 언어가 공유하는 것은 `protocol/`뿐이다. 생성물(TS 타입 · Swift Codable)은 스키마에서 나오며 손으로 고치지 않는다

## 3. 실패 층

- 못 일어나는 일은 타입으로 막는다
- 던지는 것은 CLI 실행 자체의 실패뿐이다. 프로세스 없음 · JSON 깨짐
- 게임이 거절한 것(날개 부족 · 가방 가득 · 로그인 화면 · 팝업 대기)은 예외가 아니라 값이다. 에이전트에게 도구 결과로 돌아가야 에이전트가 보고 판단한다. 예외로 바꾸면 에이전트가 못 보고 재시도한다

## 4. 타입

- TS `strict`. 명시적 `any` 0
- 갈아끼울 인터페이스는 구현체 둘이 실재할 때만 둔다. 커넥터는 처음부터 둘(실물 · 가짜)이므로 인터페이스가 있다

## 5. 하지 않는 것

- 이름 없는 유틸 파일 (`utils.ts` · `helpers.ts` · `common.ts`)
- 쓰는 곳 하나인 추상화
- 미래를 위한 파라미터
- 입력 합성 라이브러리(키 · 마우스 자동화). 팝업 자동 클릭의 재료가 된다

## 6. 테스트

- 이름이 요구를 말한다. 「무엇이 어떻게 되어야 한다」
- 기대값이 구현의 복사가 아니다
- 녹화(`recordings/`)를 픽스처로 쓴다
- LLM 시나리오(에이전트가 올바른 순서로 도구를 부르는가)는 손으로 돌린다. 게이트가 아니다

## 7. 문구

- 사용자에게 보이는 문구는 담백하게. 감탄 · 사과 · 과장 없이
- em dash 금지

## 8. 리뷰어가 보는 넷

1. 우회 냄새. 보호 장치 · 작업 관리 · 승인을 돌아가는 경로
2. 계약의 의미층. 1절이 코드에 지켜졌는가
3. 위 규칙(2~7절)
4. 테스트가 명세인가

## 코드가 나오면 정한다

M1 끝 무렵 실물 코드에서 뽑는다. 파일의 집 · 화면 상태는 누가 갖는가 · 공용 조각을 뽑는 시점 · 안 쓰는 export를 잴 도구.
