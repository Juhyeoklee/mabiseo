# 주석 규칙

**기본값은 주석 없음이다.** 남기는 쪽에 입증 책임이 있다. 쓸 때도 리뷰 때와 같은 질문을 한다. *이 주석을 지우고 순진하게 고치면 버그 · 정책 위반 · 데이터 오염이 나는가.* 아니면 쓰지 않는다.

## 남는 두 부류

1. **코드 밖 사실.** 코드를 아무리 읽어도 알 수 없는 외부 제약
   - 날개는 호출 1회당 5개, 수량 무관
   - 채집은 1회 최대 100개
   - 커넥터 토글은 7일 미사용 시 자동 OFF
   - 1시간 팝업은 PC 화면에서 확인해야 이후 요청이 처리된다
   - 로그인 · 캐릭터 선택 화면에서는 CLI가 동작하지 않는다
   - M0 녹화로 확인된 CLI의 성질
2. **지뢰방지.** 순진하게 고치면 터지는 자리
   - 맡기기 호출을 `tools/` 밖으로 옮기면 날개 예산이 우회된다
   - 활동을 겹쳐 부르면 앞 활동이 조용히 취소된다
   - 거절 응답을 예외로 바꾸면 에이전트가 못 보고 재시도한다

## 쓰는 법

- 한국어로 쓴다. 식별자는 영어
- 외부 사실은 상수 파일 한 곳에 두고 출처를 단다. 공지 번호(`3541579`) 또는 녹화 파일 이름
- 파일 머리 주석을 두지 않는다
- 기계가 막는 실수(계약 검사 · 의존 방향 대조 · 타입)는 적지 않는다
- 문서의 `§`를 가리키지 않는다. 가리켜도 되는 것은 코드 심볼 · CLI 명령 이름 · 화면 ID(`01` `02` `D1`) · 공지 번호 · 녹화 파일 이름
- 임시나 추후 작업은 `TODO(이름):` 형식

## 이관처

- 「왜 이렇게 설계했나」는 커밋 메시지로
- 결정이 바뀌면 `docs/skeleton.md`의 결정 표로

## 세지 않는다

길이나 개수를 재는 자를 두지 않는다. 판정은 위 질문 하나로 한다.
