# /kickoff — 세션 시작

세션은 이슈 하나로 시작한다. 세션과 이슈는 1:1이 아니다. 킥오프가 이 세션이 그 이슈를 **닫는지 이어가는지** 정한다.

세션의 성공은 킥오프에서 정한 **닫힘 조건**으로 잰다. 게이트 초록과 리뷰는 전제이지 목표가 아니다.

## 0. 계정 확인

`gh auth status`. 활성 계정이 `Juhyeoklee`가 아니면 `gh auth switch --user Juhyeoklee`.

## 1. 이슈 고르기

```
gh api repos/Juhyeoklee/mabiseo/milestones --jq '.[] | "\(.number) \(.title) 열림 \(.open_issues) 닫힘 \(.closed_issues)"'
gh issue list --milestone "<현재 마일스톤>" --state open
```

가장 낮은 번호의 열린 마일스톤이 현재다. 그 안의 이슈 하나를 사용자와 고른다. 이슈가 없으면 사용자와 하나를 만든다.

**이슈 본문은 세 줄이다.** 서사를 쓰지 않는다.

```
무엇: <이 이슈가 끝나면 생기는 것>
완료 조건: <어떤 상태면 닫히는가>
실물 관문: <Windows에서 몇 판 · 어느 신호원 · 없으면 「없음」>
```

라벨은 마일스톤 태그(`m0` …). 하네스 자체를 고치는 이슈는 마일스톤 없이 `하네스` 라벨을 단다. 판정 불가는 `재판정` 라벨을 달고 제목에 재판정 사건을 적는다(*1시간 넘게 써 봤을 때* 등).

## 2. 합의 다섯

사용자와 다섯을 맞춘다. 맞기 전에 코드를 쓰지 않는다.

1. **닫힘 조건** — 닫을 때 확인할 수 있는 상태. 「정리한다」, 「개선한다」는 조건이 아니다. 이슈를 **닫는다 / 이어간다**도 여기서 정한다
2. **무엇** — 이 세션이 만드는 것 한 줄
3. **실물 관문** — 몇 판 · 어느 신호원 (Mac 가짜 / Windows 실물). 신호원 표는 `CLAUDE.md`
4. **안 하는 것** — 범위 밖으로 미리 둔다. 금지선 「범위 추가」의 기준은 닫힘 조건이다
5. **비용 예산** — 날개(맡기기 호출 수) · API

## 3. 킥오프 댓글

맞춘 닫힘 조건은 이슈 댓글에 산다. 세션마다 댓글 둘, 킥오프 때 하나와 닫을 때 하나. `/review`가 0단계에서 이 댓글을 읽는다.

```
gh issue comment <이슈번호> --body "세션 목표
닫힘 조건: …
확인: …
판정자: 에이전트 | 사용자
이슈: 닫는다 | 이어간다"
```

세션 도중 조건이 틀렸다고 드러나면 그 자리에서 사용자 판정으로 바꾸고 댓글을 갱신한다. 조용히 바꾸지 않는다.

## 4. 브랜치

```
git checkout main && git pull
git checkout -b s/<이슈번호>-<이름>
```

## 5. 만들기의 규칙

- **가짜 커넥터로 먼저.** 기본값은 가짜, 실물은 Windows에서만 켜진다. 실패 재현은 `--fail=wings|bag|popup|offline|login`
- **실물 전용 세션을 허용한다.** M0처럼 녹화가 없어 「가짜 먼저」가 성립하지 않으면 Windows에서 바로 한다. 새로 본 응답 모양은 `recordings/`에 추가하고 즉시 커밋한다
- 관측은 에이전트가, 입력(탭 · 스크롤 · PC 화면 확인)은 사용자에게 요청한다
- 기존 코드의 결함에 맞추느라 새 코드가 기이해지면 우회를 완성하지 말고 멈춘다
- 세션 플랜은 세션 안에서 세우고 버린다. 파일로 남기지 않는다

## 6. 금지선

넘기 전에 사용자에게 묻는다.

- 날개를 쓰는 호출
- 채팅 전송
- 프로토콜 계약(`protocol/`) 변경
- 범위 추가 — 기준은 킥오프 댓글의 닫힘 조건. 그 밖이면 범위 추가다

**팝업 자동 클릭은 묻지도 않는다. 영구 금지.**

## 7. 닫기

`/review`가 순서를 진다. 닫힘 조건 대조 → gates.sh → 코드 리뷰 1회 → 주석 리뷰 1회 → 이관 → gates.sh 재실행 → 커밋 → main에 머지(스쿼시 안 함). 이슈가 「닫는다」면 `Closes #n`, 「이어간다」면 `Refs #n`. 커밋과 머지는 사용자 승인.

닫힘 조건에 미달이면 사용자가 고른다. 조건을 명시적으로 줄여 닫거나, 머지하지 않고 브랜치를 둔다. 어느 쪽이든 결과 댓글은 단다. 인계문을 쓰지 않는다.
