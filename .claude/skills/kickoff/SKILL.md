# /kickoff — 세션 시작

세션은 이슈 하나로 시작하고 그 이슈를 닫으며 끝난다. 성공의 자는 하나다. **이 세션에서 코드가 나왔는가.**

## 0. 계정 확인

`gh auth status`. 활성 계정이 `Juhyeoklee`가 아니면 `gh auth switch --user Juhyeoklee`.

## 1. 이슈 고르기

```
gh api repos/Juhyeoklee/mabiseo/milestones --jq '.[] | "\(.number) \(.title) 열림 \(.open_issues) 닫힘 \(.closed_issues)"'
gh issue list --milestone "<현재 마일스톤>" --state open
```

가장 낮은 번호의 열린 마일스톤이 현재다. 그 안의 이슈 하나를 사용자와 고른다. 이슈가 없으면 사용자와 하나를 만든다.

**이슈 본문은 세 줄이다.** 서사를 쓰지 않는다.

```
무엇: <이 이슈가 끝나면 생기는 것>
완료 조건: <어떤 상태면 닫히는가>
실물 관문: <Windows에서 몇 판 · 어느 신호원 · 없으면 「없음」>
```

라벨은 마일스톤 태그(`m0` …). 판정 불가는 `재판정` 라벨을 달고 제목에 재판정 사건을 적는다(*1시간 넘게 써 봤을 때* 등).

## 2. 합의 넷

사용자와 넷을 맞춘다. 맞기 전에 코드를 쓰지 않는다.

1. **무엇** — 이 세션이 만드는 것 한 줄
2. **실물 관문** — 몇 판 · 어느 신호원 (Mac 가짜 / Windows 실물). 신호원 표는 `CLAUDE.md`
3. **안 하는 것** — 범위 밖으로 미리 둔다
4. **비용 예산** — 날개(맡기기 호출 수) · API

## 3. 브랜치

```
git checkout main && git pull
git checkout -b s/<이슈번호>-<이름>
```

## 4. 만들기의 규칙

- **가짜 커넥터로 먼저.** 기본값은 가짜, 실물은 Windows에서만 켜진다. 실패 재현은 `--fail=wings|bag|popup|offline|login`
- **실물 전용 세션을 허용한다.** M0처럼 녹화가 없어 「가짜 먼저」가 성립하지 않으면 Windows에서 바로 한다. 새로 본 응답 모양은 `recordings/`에 추가하고 즉시 커밋한다
- 관측은 에이전트가, 입력(탭 · 스크롤 · PC 화면 확인)은 사용자에게 요청한다
- 기존 코드의 결함에 맞추느라 새 코드가 기이해지면 우회를 완성하지 말고 멈춘다
- 세션 플랜은 세션 안에서 세우고 버린다. 파일로 남기지 않는다

## 5. 금지선

넘기 전에 사용자에게 묻는다.

- 날개를 쓰는 호출
- 채팅 전송
- 프로토콜 계약(`protocol/`) 변경
- 범위 추가

**팝업 자동 클릭은 묻지도 않는다. 영구 금지.**

## 6. 닫기

`/review`가 순서를 진다. gates.sh → 코드 리뷰 1회 → 주석 리뷰 1회 → 이관 → gates.sh 재실행 → 커밋 → main에 머지(`Closes #n`, 스쿼시 안 함). 커밋과 머지는 사용자 승인.

못 끝낸 세션은 이슈에 댓글 한 줄. 인계문을 쓰지 않는다.
